UI Flow Diagrams — Phase 1 Product: Offline-first exhibition lead capture + event ROI platform Version: 1.0 Files: flow-1-preauth-onboarding.svg · flow-2-showday-weekly.svg · flow-3-upgrade-pro.svg Reading conventions Colour Meaning Grey Shared / neutral screens — pre-auth spine, home, free-tier states Teal Rep-facing, at the venue, works fully offline Purple Admin-facing or post-show, requires connectivity Amber Monetization screens. Only two exist in the whole product. Boxes are screens. Arrows are transitions. Nothing in these diagrams is a background process — sync is deliberately invisible and therefore undrawn. Diagram 1 — Pre-auth and onboarding flow-1-preauth-onboarding.svg Covers landing page → signup → the fork → two onboarding paths → home. Key structural point: the fork question (&quot;team, or just yourself?&quot;) is the only branch in the entire pre-auth flow, and both branches converge on the same home screen. The solo path exists to deliver value in 90 seconds via the digital card; the admin path exists to get one event configured, because an admin with no event has bought nothing. Screens to build: landing, OTP entry, name/company, fork, card builder, card preview, share sheet, event creation, event cost, rep invite, custom fields, template editor, home. Diagram 2 — Show day and weekly flow-2-showday-weekly.svg Covers the capture loop, the evening ritual, and the following week. Key structural point: the teal-to-purple transition is also the sync boundary. Everything teal happens at the venue with no network assumption. Everything purple assumes connectivity and post-processed data (transcripts, summaries, aggregated counts). The top row repeats hundreds of times per day. Optimising anything else in the product before this row is four seconds is a misallocation. Screens to build: home/scan, camera, confirm (incl. duplicate flag), voice capture, evening review, qualification, bulk send queue, today's follow-ups, call/log outcome, deal won entry, ROI dashboard. Diagram 3 — Upgrade path and Pro unlock flow-3-upgrade-pro.svg Covers the 100-lead wall through to Pro features. Key structural point: the paywall sheet fires after the save completes, never in place of it. A rep blocked mid-rush becomes an active opponent of the product. Four triggers reach the same paywall sheet. Only the primary one is drawn: Lead 101 saved on a free account (strongest — fires mid-rush, mid-success) Fourth voice note attempted Greyed ROI panel tapped after a show Second user invited Build the paywall sheet once with a variable headline, and trigger it from four places. Do not design four upsell screens. Not covered in these diagrams Settings, profile editing, event switching, lead list filtering, search, export, error and empty states, and the offline/sync status indicator. All are needed for the build; none carry structural decisions worth drawing. The dormant gap between onboarding and show day is also absent, because nothing in it happens inside the app — it is a WhatsApp message. See the user journey doc, stage 4.
